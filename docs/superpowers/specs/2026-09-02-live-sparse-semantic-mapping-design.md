# 实时稀疏语义建图模式设计（方案 A）

## 目标

新增与原始 rosbag 采集模式并列的“实时稀疏建图模式”。该模式持续运行 RGB-D SLAM 以显示当前轨迹和地图，但只对受限关键帧异步执行语义分割与标注，以降低 GPU/CPU 压力和长期存储量。

## 非目标与验证边界

首版不证明 RGB-depth 对齐、时间同步、ATE/RPE、回环质量、全局绝对坐标、语义精度、导航或安全性能。对象锚点标记为 `observed_in_live_map` 且 `global_accuracy: unvalidated`；它们可在 SLAM 回环优化后更新，但不应被称为已验证的全局语义地图。该模式不控制底盘，实时密集深度缓存不能替代安全控制器。

## 用户模式

- **采集模式**：保持现有 rosbag 工作流，用于调试、标定和可审计原始记录。
- **实时建图模式**：默认不录制完整 rosbag。仅当操作者显式勾选“同时录制原始 bag（调试）”时才保存全帧原始数据。

## 架构

```text
Gemini 335 RGB-D/IMU
  ├─ RTAB-Map RGB-D 前端（连续） → 当前轨迹、局部/压缩地图、SLAM 状态
  └─ 关键帧门控器 → 单槽最新帧队列 → 异步语义 worker → 对象去重存储
                                                        └→ 实时 UI 对象列表
```

RTAB-Map 是实时定位/地图基线。关键帧选择为任一条件满足：距上次语义帧至少 1 秒、相对最近语义帧平移至少 0.35 m、或旋转至少 15°。队列容量固定为 1；worker 忙时用较新的关键帧替换较旧任务。语义 worker 不阻塞 SLAM 或 UI。

## 数据与保留策略

长期保存：RTAB-Map 地图/轨迹导出、关键帧缩略图、对象 JSON、关键帧位姿/时间戳和运行 manifest。运行时保存：最近深度/点云/预览缓存。默认不保存整段 RGB-D rosbag。每个对象记录类别候选、粗 3D anchor、证据关键帧、置信度、关联状态和最后观测时间；按现有同类空间门限去重。

## 页面与 API

现有 localhost 控制台新增模式选择。实时模式显示 RGB、深度伪彩、RTAB-Map 状态、轨迹/地图链接或嵌入视图、关键帧接受/丢弃数、语义队列状态、对象列表和明确的“全局精度未验证”标记。开始/停止 API 传递模式和 raw-bag 选项；状态 API 返回 SLAM/关键帧/语义 worker 指标。历史运行继续可查看 manifest、地图导出、对象 JSON 与日志。

## 启动与故障处理

启动前检查 `/dev/video*`、所需 ROS 话题、RTAB-Map 包和模型运行时。任何缺失依赖都应明确标为 `unavailable`，不能伪造轨迹/地图。RGB、depth、camera_info 或必要 TF 断流时显示告警；语义推理超时/失败只记录失败并继续 SLAM。停止时按依赖逆序退出 worker、RTAB-Map、驱动，保存 manifest、对象快照和可用地图导出。

## 验证

对关键帧门控、单槽覆盖队列、对象去重、模式请求校验和 manifest 状态做单元/API 测试。用 dry-run 验证命令构成与 UI 状态；用短时受监护的 Gemini 335 室内运行验证话题和实时链路。硬件运行只构成链路证据，不能提升项目 `proposal_ready; prototype_validation_pending` 状态。
